## 文件头：`0x1298EB0`

该函数：

1. 逐字节要求偏移 `+0x00..+0x03` 为 `VTBF`，否则返回 `-2`。
2. 将 `+0x08..+0x0B` 四字节复制为格式标签。
3. 将 `+0x0C..+0x0D` 按小端 `u16` 读取为顶层块数。
4. 将读取游标设为文件起点 `+0x10`。

该函数没有读取 `+0x04..+0x07` 或 `+0x0E..+0x0F`。在找到其他消费代码前，这六个字节必须保持为未知原始数据，不能命名为 version 或 header extra。

`0xA9F220` 调用该函数后要求格式标签为 `SRFF`，按顶层块数循环读取块，并且只对标签 `SRCK` 调用 Surfride 项目解析器。

## 块头：`0x1298240`、`0x12983D0`

`0x1298240`：

- 逐字节要求 `+0x00..+0x03` 为 `vtc0`，否则返回 `-3`。
- 将 `+0x04..+0x07` 按小端 `u32` 读取为块自己的长度字段。

`0x12983D0` 在上述子头有效时：

- 复制 `+0x08..+0x0B` 为四字节块标签。
- 将 `+0x0C..+0x0D` 读取为子块数。
- 将 `+0x0E..+0x0F` 读取为属性数。
- 将属性游标设为块起点 `+0x10`。
- 将主流游标设为 `block_start + 8 + size_field`。

因此子块从 `block_start + 8 + size_field` 开始；属性由独立游标从 `block_start + 0x10` 读取。未知/非法子头的跳过行为还需单独审计，编辑器不能用它作为接受损坏文件的依据。

## 属性描述符：`0x12984B0`

首两字节：

```text
+0x00 code: u8
+0x01 flags: u8
type       = flags & 0x3F
has_mult   = (flags >> 6) & 1
has_count  = (flags >> 7) & 1
```

若 `has_mult` 或 `has_count` 为真，继续读取一个扩展字节：

- count 编码只检查 `ext & 0x18`。
- `0x08`：读取一字节值；`count = value + 1`。
- `0x10`：读取小端两字节值；`count = value + 1`。
- `0x18`：读取小端四字节值；`count = value + 1`。
- 其他值不读取额外 count 字节，默认 count 保持 1。
- mult 使用 `ext & 7` 索引只读表 `0x19A73C8`。

`0x19A73C8` 的八项 `u32` 值为：

```text
[2, 3, 4, 9, 16, 0, 0, 0]
```

非字符串属性的下一属性位置为：

```text
value_ptr + count * mult * type_size[type]
```

`0x19A7388` 的前 16 项 `i32` 类型大小为：

```text
[0, 1, -1, 1, 1, 2, 2, 2, 4, 4, 4, 4, 4, 8, 0, -1]
```

旧解析器遗漏了 type 13 的 8 字节大小，并把 count mode 解读为五位值；这两点均不能移植。

## 字节串：`0x12984B0`、`0x1298360`

type 2 使用长度前缀：

- 首字节最高位为 0：长度就是该字节，数据从下一字节开始。
- 首字节最高位为 1：长度为 `((first & 0x7F) << 8) | second`，数据从第二个长度字节后开始。

游戏读取器不要求短字符串使用单字节形式。现有样本中确实存在小于 `0x80` 字节但使用双字节前缀的值，因此编辑器必须保留原始前缀形式。

该层只复制原始字节并补 NUL，不执行 UTF-8 校验。文本编码语义必须从上层文本消费代码证明。

## 标量读取

- `0x12994B0` 按无符号目标读取标量并推进 value pointer。
- `0x1298F30` 对 type 3 使用有符号 8 位，对 type 5/7 使用有符号 16 位，对 type 6 使用无符号 16 位。
- `0x1298600` 将整数类型转换为 `f32`；type 10 的四字节原始位模式直接作为 `f32`。

type code 的业务名称不能仅由这些转换函数推断；需要结合每个标签、属性 code 的具体调用点确认。
